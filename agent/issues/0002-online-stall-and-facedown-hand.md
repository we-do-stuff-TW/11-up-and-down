# 0002 — 線上多人：一輪結束就卡著不動；換局後手牌背面朝上躺在桌上

狀態：已解決（客端已改，待 push）
發現：2026-09-22（Francis 回報，房號 3CGE、立體牌桌、三個真人）
嚴重度：高（整桌停住；自己的牌看不到）
相關：[`agent/reports/0003-online-stall/`](../reports/0003-online-stall/README.md)、issue 0001 / plan 0004（同一天另一條手牌的病）

## 症狀（兩張截圖）

1. 第 16 局最後一墩打完，「WeiYu 收下這一墩」之後整桌不動，牌堆一直躺在桌心。
2. 第 17 局叫墩中：我的 5 張牌**背面朝上、平躺在自己面前的桌上**，攤成一排，
   別人的牌、骰子、王牌都正常。
   Francis 另外說「越玩越當」。

## 查到什麼

### 截圖 2：接力的兩段補間在同一格內一起到期時，是倒著處理的（查過、已重現）

立體桌發我的牌是兩段接力：先一張一張飛到我面前落桌（背面朝上，`dealSlot`），整輪發完停 300ms
再一起拿起來翻正扇開（`queue:true` 排在前一段後面）。`stepTweens()` 原本從陣列尾端往前走，
平常一格 16ms 兩段不會同時到期；但一格拖太久（分頁切走、GC、換局那一格新材質在編譯著色器、
手機卡一下），兩段一起到期時：**後段先套到終點（手上、翻正），前段再把它蓋回自己的終點
（桌上、背面）**。牌就永遠背面躺在中繼站，直到 slot 變了（輪到我出牌）才會動。
其他 `queue:true` 的接力（收墩前聚成一疊）同樣會中，只是間隔較長、較少見。

無頭 Chrome（swiftshader，一格好幾百毫秒）每次都重現：改之前五張牌 `flip=3.14, rx=-1.57, z=2.46`
（＝`dealSlot`），改之後 `flip=0, rx=-1.04, z≈3.1`（＝`handSlot`）。截圖見 report 0003。

### 截圖 1：只有一個人負責敲伺服器，他不在時全桌等他 30 秒（查過機制；哪一台不在是推論）

連線模式的節奏（AI 出牌、收墩、下一局）靠客端每 420ms 敲 `tick`／`next`，
**只有「在座第一位還在線的真人」會敲**（`isLive` 看 `seen` 30 秒內）。
他手機鎖了、切去看訊息、分頁被瀏覽器凍住、或那一趟請求卡在半路——他的 `seen` 還新鮮，
其他人都乖乖等，30 秒後 `seen` 過期才遞補。一局打完正是大家低頭看手機的時候，
所以最常卡在「一輪結束就不動了」。這一場 ticker 是 WeiYu（0 號）；她那台當時在做什麼我查不到（推論）。

### 「越玩越當」：客端資源沒有增長（查過）

假伺服器照真實時序（HTTP 0.3s、realtime 再到一次、每 0.7s 一列心跳列）把 21 局推完，
立體與平面各跑一次，每局量一次：

| | 立體 | 平面 |
|---|---|---|
| JS heap | 15–22 MB，不隨局數長 | 3.5–4.5 MB |
| 補間／牌物件／場景子物件 | 每局收乾淨 | — |
| WebGL 幾何／貼圖／程式 | 135–148 / 44 / 43，穩定 | — |
| DOM 節點 | 3050–3290 | 3050–3290 |
| applyRow 平均耗時 | 1.1–1.5 ms，不隨局數長 | 0.8–1.1 ms |

所以不是漏記憶體。「越玩越當」我推測是上面兩個機制的體感：局數越多、越到後面大家越常低頭，
卡住的機會越多；再加上一趟請求掛住時整條隊伍（含你按下去的牌）都排在它後面。

### 沒查到

- `touch_seen`（心跳寫 `seen` 的 SQL 函式）的定義不在 repo 裡（`migrations/` 沒有 0002、0003），
  會不會順手動到 `rev` 我沒查到。客端兩種情形都撐得住。

## 修法（全在 `docs/index.html`，不動 Edge Function、不動 migration）

1. **`stepTweens()` 改成由舊到新處理**（走複本、動手前確認那一段還在）：兩段一起到期時，
   前段先到終點，後段從那裡接手到自己的終點。
2. **補敲**：這一格停得比該停的久超過 `BACKUP_GRACE`（4 秒），其他在線的真人就補敲一發
   `tick`／`next`。伺服器有樂觀鎖與 phase 檢查，多敲只會落空。`next` 被打回的「這局還沒結束」不再印出來。
3. **一趟最多等多久**：`accessToken()` 6 秒、`fetch` 12 秒（`AbortController`）。時間到當它失敗：
   `busy` 放掉、隊伍往前走、出牌那手退回手上（伺服器其實收到了的話下一列推播會擺回去）。
   `?trace=1` 會記 `api!` 與 `tick backup`。
