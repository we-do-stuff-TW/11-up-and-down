## 查實的缺陷（獨立於這次回報，沒修）

1. **自動降畫質量錯了時鐘。** `docs/index.html:8934` 起算、`:8956` 止，`dt = performance.now() - t0` 量的是 CPU 把指令交出去的時間，不是 GPU 畫完的時間。同一時刻頁面自己以為的 `FX.ms` 是 1.1–2.5 ms，實際（GPU 做完）是 7–14 ms，差約 8 倍。門檻 `FX_SLOW_MS = 26`（`:8798`）因此在「GPU 追不上」的機器上**永遠不會觸發**；`:7242` 的註解寫「慢了自己往下降」，實際做不到。
2. **開機的編譯尖峰會誤降檔。** `:8957` 的平均第一筆直接拿 `dt` 起算，而第一筆含著色器編譯（量到單格 1.5–3.6 秒）；前 30 格雖然不下決定，那一筆還留在平均裡：1500 ms × 0.9³⁰ ≈ 63 ms ＞ 26，30 格後就掉一檔，換檔又重編譯又掉一檔。實測：冷啟動一次從高掉到低（`FX.ms` 56→135），暖啟動四次都停在高。結果是**同一台機器、同一份程式，畫質看「這次開機編譯多慢」而定**。
3. `ud.trace=1` 被存成永遠開（`:6416` 起）。沒有效能代價，但是偵錯用具長期留在他的瀏覽器裡，且沒有任何地方告訴他它開著。
