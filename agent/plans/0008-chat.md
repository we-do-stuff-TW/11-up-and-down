狀態：已上線（2026-10-31），等真人用手機實測（步驟 7）。資料庫 0009、函式第 12 版、網頁都上了；立體 4 人桌字幕壓住你出的牌那件，上線後他用手機看再決定。11-01 他回報「話多了版面跟著放大」：修好、還沒推（見「上線後的修正」）

## 目標

一句話：同一桌的人，在開房頁等人的時候、牌局打到一半的時候，都能打字講話，別人馬上看得到；鎖螢幕回來不漏。

## 現況（2026-10-30 查過）

- 遊戲裡沒有任何聊天或表情功能（`docs/index.html` 搜 chat／聊天／表情 零筆）。
- 每一桌已經有一條即時頻道 `room-<房號>`（`subscribe()`），收 `rooms` 那一列的變化，外加別人出牌的 broadcast `move`。頻道沒有設成私有（`channel()` 沒帶 `private:true`），知道房號的人都接得上。
- 所有寫入都經過函式 `game`；`rooms` 公開可讀、`hands` 一條 policy 都沒有（README「誰看得到什麼」）。函式認人：`players.user_id → pid`（`resolvePid`），座位在 `rooms.seats[].pid`。
- 手機的即時頻道常常斷：2026-10-08 房間 5527 二十分鐘重接至少 10 次（`chanStatus` 檔頭）。斷著的那段 broadcast 不會補送。
- 鍵盤：牌局只用 Esc（關設定頁、計分表，`docs/index.html` keydown 那段），Enter 只在大廳房號欄。牌局中「按 Enter 開始打字」不撞現有的鍵。
- 房間會不會被清掉：repo 裡沒找到刪 `rooms` 的程式（函式、migration 都沒有）；可能在 repo 以外（資料庫排程），沒查。

## 存不存（10-31 照建議：存）

- **存（建議）**：新表 `chat`。鎖螢幕、切去 LINE 回來會補上漏掉的；晚進來的人看得到前面聊的；只有坐在這桌的人讀得到。要多一支 migration（請他在 SQL Editor 貼）。
- **不存**：只走現有頻道的 broadcast。不動資料庫，但斷線那段就是漏了；知道房號的人接得上頻道，聽得到、也能冒名講話（重新整理才不見）。

### 「存」的做法（我推測可行，動工時逐條驗）

- `0009_chat.sql`：`chat(id bigserial, code text, match int, pid text, name text, body text, at timestamptz)`，`body` 1–100 字（10-31 從 200 降）。RLS 開著，**沒有寫入 policy**（照 `hands`／`rooms` 的路：只有函式寫得進去）；一條 select policy：`auth.uid()` 對到的 `players.pid` 坐在 `rooms.seats` 裡才讀得到。加進 realtime publication。
  - ⚠️ policy 不能直接查 `players`：線上 `players` RLS 開著、**一條 policy 都沒有**（10-31 用連線器查 `pg_policies`／`pg_class`，查過），瀏覽器身分查它永遠是空的＝誰都讀不到。要包一支 `security definer` 小函式「這個 uid 坐不坐在這一桌」，policy 叫它。`players.pid` 是 uuid、`rooms.seats` 是 jsonb（查過），比對時 `seats` 裡的 pid 要轉字串比。
  - 同一次查到：`rooms` 有一條 `rooms_public_read`（`true`），publication `supabase_realtime` 只有 `rooms`。
- 函式 `game` 新動作 `say`：驗你坐在這桌、字數、太快就擋（每人每秒一句上下，數字動工時定），insert 一列。**不碰 `rooms`、不動 rev**（架構不變量：牌局只走 `game_commit`）。另一個動作 `chat`：拿「某個 id 之後」的紀錄。
- 手機：同一條 `room-<房號>` 頻道多聽 `chat` 表的 insert（filter `code=eq.<房號>`）；每次接上（含重接）跟進房時，用 `chat` 把漏的補回來（跟 `chanStatus` 收到 SUBSCRIBED 就問 state 同一個時機）。自己送的那句先畫出來，回話到了再對上 id。
- 要驗的：realtime 的 postgres_changes 會不會照這條 select policy 只推給坐在桌上的人（我推測會，沒查證）；延遲大概跟 `rooms` 一樣約一秒，要不要再加 broadcast 搶快，量了再說。
- 「再來一場」：同一個房號同一串，不清空。聊天留多久跟著房間走（見現況最後一條）。
