# 0006 — 一步牌局：多人線上「越玩越當」的六條路從源頭收掉

狀態：已上線（2026-10-18；SQL、函式、網頁三半都核過）；等真人多人實測
開工：2026-10-18（Francis 看完架構健檢報告回「全修吧」）

## 目標

一句話：伺服器的每一步「房間與手牌一起改、或都不改」並且說得出結果；手機不再因為背景雜訊把你的按鈕收掉、把你那一手抹掉。

## 病灶（2026-10-17 架構健檢，報告在 `$TMPDIR/architecture-review-20261017-031727.html`）

| # | 使用者看到的 | 病根（查過的位置） |
|---|---|---|
| 1 | 房主離開 30 秒，其他人叫墩按鈕消失 | `docs/index.html` renderStatus 的房主門。09-09 第一版是房主在本機跑引擎，那時這道門是對的；引擎搬到伺服器之後它就是遺跡 |
| 2 | 背景報到失敗一次，按鈕被紅字蓋掉最多 10 秒 | `call()` 的 catch 對背景呼叫也寫 `NET.err`，renderStatus 一看到 `NET.err` 就整列換掉 |
| 3 | 排在慢請求後面超過 6 秒，先演的骰子被抹掉，再按被 409 | `INBOX.TTL` 從按下去那一刻算，不是從送出去算 |
| 4 | 同時叫墩被吃掉、伺服器回 200 | `index.ts` `ok()` 搶頁輸了回 `{ok:true, room:fresh}` |
| 5 | 鎖屏一次→全桌補敲→有人少一張牌→最後一墩永久卡死；兩發 next→兩副牌 | `index.ts` 手牌的寫入（deal／writeHand／sim 叫墩）都在 `persist()` 樂觀鎖之前、鎖之外；房間與手牌分兩趟讀，不是同一刻 |
| 6 | 手機上的立體桌從不休息 | sync() 每一列都無條件 `dirty = 4`（只換 `seen` 的心跳列也是）；幽靈換色（`Color.equals` 被浮點誤差打破） |

## 步驟

### A. 伺服器：一步＝一個交易（候選 ①）
- [x] A1. `supabase/migrations/0007_one_step.sql`：三支只給 service_role 的函式，**只新增、不改舊物件**
  - `game_load(code)`：房間＋這一桌全部手牌，一句 SELECT（同一個快照）
  - `game_commit(code, rev, patch, pid, now, hands)`：鎖 rev → 改房間 → 改手牌，同一個交易；rev 不對回 null、什麼都不寫。`seen` 用合併的，不再整份覆寫
  - `game_seen(code, pid, now)`：報到。只合併自己那一格、不動 rev，4 秒內報過就不寫（少一列 realtime）
- [x] A2. `index.ts`：每個動作改成「載入 → 套規則（只動記憶體）→ 提交」，提交輸了就重新載入再套一次（最多 8 次：同時叫墩最壞要輸 n−1 次）。
  結果分三種：寫進去了（200，帶這一刻的房間與手牌）／不必做了（200 `idle`：別人已經做掉了，例如補敲、兩發 next）／不行（409，**帶最新的房間與手牌**讓手機退回真相）。
  戰績在提交成功之後才寫。回應多帶 `now`（伺服器時間）。`next` 收客端送的 `ri`，那一局已經開過就回 `idle`。
  牌局中房主離開，房主身分交給還在線的下一位。
- [x] A3. `scripts/server_test.ts`：**import 本體 `index.ts`**（攔 `Deno.serve` 拿 handler），資料庫換成 PGlite（真的 Postgres 16，在記憶體裡）跑 0007 的三支函式。
  重演健檢探針的三個劇本：鎖屏補敲（少一張牌）、兩發 next（兩副牌）、六人同時叫墩（被吃）。改之前紅、改之後綠。

### B. 手機：不收按鈕、不抹你那一手（候選 ②④ ＋ 單點）
- [x] B1. 拿掉房主門（2D／3D 共用同一條狀態列）
- [x] B2. 背景呼叫失敗一次不算數，連續兩次才說「連不上」；**任何時候狀態列的按鈕都留著**，錯誤只換掉那一句字
- [x] B3. 先演的那一手等到伺服器回話才作廢（不再從按下去算 6 秒）；玩家的動作插隊到排著的背景呼叫前面，正在跑的背景呼叫直接放掉
- [x] B4. 409 帶回來的房間照收（退回真相），不只是退回按之前
- [x] B5. 補敲錯開：在線的人照座位順序各晚 1.5 秒，不再同一個 420ms 視窗一起敲
- [x] B6. 在線判斷用伺服器時間（回應裡的 `now` 算出時差），手機時鐘快 30 秒不再覺得全桌離線
- [x] B7. 離開房間後舊頻道進來的列不收（以前會被拉回舊房、心跳打舊房）

### C. 畫面：沒變就不畫（候選 ⑤ 的不可見那一半 ＋ 單點）
- [x] C1. 幽靈換色：轉色收尾直接設成目標色、比較容許誤差
- [x] C2. sync() 只有真的變了才叫醒 WebGL（只換 `seen` 的列不畫）
- [x] C3. 平面「剩幾張牌」細條每出一張就全桌重演：演過就不演
- [x] C4.（10-18 Francis 看完展示頁拍板「動」）桌布轉到一半又進來一列，不再從半路重開 900ms；一格之內王牌換過去又換回來停在對的顏色。平面的 CSS 過場本來就不會重開，加測試釘住

## 不做什麼（這一輪）

- **看得到的節奏改動**：手機上壁爐的火每 0.15 秒一格、輪到我叫墩時環的呼吸 60fps——要改就是畫面會變，先出樣品給 Francis 挑，不在這一輪。
- **候選 ⑥ 規則只留一份**：要放掉 ADR 0001「單檔、無建置」的前提。這一輪改用 A3 讓伺服器的狀態機第一次有測試，漂移的風險先由測試接住。
- **伺服器自己推時間（候選 ③ 的完整版）**：補敲在 A 之後變安全、B5 之後變稀疏，先不搬。
- `touch_seen` 不改也不刪（線上定義沒查到；新函式不叫它）。

## 上線順序（Francis 跑）

1. Supabase 後台 SQL Editor 貼 `0007_one_step.sql`（只新增函式，舊版伺服器照常）
