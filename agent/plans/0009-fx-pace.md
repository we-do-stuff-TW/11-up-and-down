# 0009 — 自動降畫質改看「GPU 真的做完一格」的延遲；`?fps=1` 讀數

狀態：已上線（2026-11-01 他看完回「可以」；diff 套進 `docs/index.html`，idle_test 45 項（「自己降檔」那段改餵欠帳）、ui_test 18 項、pace.ts 兩種情境都過），等他和朋友開 `?fps=1` 念數字。改法留在旁邊的 `0009-fx-pace.diff`。
開題：issue 0006（10-28 他回報「非常 lag、120 幀變 12」；11-01「不管電腦好壞只有低才順」「有動作就會頓」「你測」「繼續吧」）

## 目標

一句話：慢的機器一有動作就自己降到追得上的那一檔（設定頁本來就是這樣承諾的：「慢了會自己往下降」），不要停在高檔每秒 8 格；順便給一行真數字，他和朋友開 `?fps=1` 玩一局截圖，就有證據。

## 為什麼現在做不到（查過，細節在 issue 0006）

- 缺陷一：現在的自動降檔量的是 CPU 把指令交出去的時間（`fxRender()` 裡的 `dt`，`docs/index.html:9611`），門檻 26ms。GPU 追不上的時候 CPU 照樣 2ms 就交完，所以**永遠到不了門檻**。真機紅綠燈：把畫布放大到 4426×2151 逼 M1 Ultra 追不上，GPU 延遲 120ms（每秒約 8 格），頁面自己量到 1.8ms，從頭到尾停在高（`pace.ts`，`nov01-gpu-dpr25`）。
- 缺陷二：開機第一格含著色器編譯（量到 1.5–3.6 秒），留在平均裡，30 格後誤降一檔；再編譯再降。
- 缺陷三：`ud.trace=1` 存成永遠開，沒有地方告訴使用者它開著。這次的讀數刻意只看網址、不存。
- 高檔在他的畫布就把 M1 Ultra 吃滿（98–99%），弱的機器一定追不上；同一塊 4426×2151 的畫布中檔 17ms、高檔 120ms，差 7 倍——高檔的接觸陰影（GTAO）隨像素數暴漲。

## 怎麼改（`0009-fx-pace.diff`，87 行加減，只在立體那層；平面那層沒有檔位的概念，不用動）

1. **用 fence 量 GPU。** 「有東西在動」的那一格畫完後放一支 fence（WebGL2 `fenceSync`），之後**每一格**（不只動的那幾格）用 0 毫秒的 `clientWaitSync` 問做完了沒；第一次聽到做完那一格的時間戳減掉放 fence 那一格＝GPU 從收到到做完的延遲。順的時候是一到兩格（60Hz 約 17ms）。沒有 WebGL2 的退回看相鄰兩格 rAF 的間隔。
2. **門檻。** 換管線／開機後 1.5 秒內、而且前 3 筆不算（缺陷二）；單筆超過 1000ms 封頂不丟（丟掉的話慢到一格 1 秒以上的機器反而永遠不降）；每一筆「超過 60ms 的部分」累積成欠帳，順的每一筆還 100ms，欠到 1500ms 就降一檔——每格慢 120ms 的機器約 3 秒降、一格 1 秒的機器兩筆就降，單一次切走分頁（一筆封頂 940）不會降；鎖定的檔位（設定選了高／中／低）照樣不動。第一版用「連續 20 格」數格數，在每秒 3 格的軟體算繪上一支 fence 三秒才回一筆，等一分鐘都降不了，才改成算時間。
3. **`?fps=1`。** 畫布右上角一行：`每秒 N 格 · 延遲 Nms（平均 N）· 像素 · 檔位（自動／鎖）`。貼在 `.table` 裡（立體時 relative），不蓋頂列按鈕、不蓋右欄。截圖：`0009-fps-box.png`。
4. 拿掉 `FX_SLOW_MS` 與那段 CPU 時間的判斷；`FX.ms` 留著給 `UD.fx()` 看。

## 使用者會看到什麼

- 自動檔（沒在設定裡選過檔位的人，多半是朋友）：慢的機器上開打幾秒後畫面變成中或低（本來就有的那三種長相，沒有新的），之後順；快的機器什麼都不變。
- 鎖「高」的人（他現在就是）：什麼都不變；想知道數字就在網址後面加 `?fps=1`。
- 沒有新的提示、沒有會消失的訊息。
