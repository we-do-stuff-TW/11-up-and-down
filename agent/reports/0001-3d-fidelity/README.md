## 做了什麼

立體牌桌最不像真的地方不是零件不夠細，是**光**：整間房均勻亮、沒有接觸陰影，
所以牌看起來像浮在桌上、書櫃像一張貼圖。Francis 在原型上逐項切過九層之後定案六層，
全部做進 `docs/index.html` 的 3D 呈現層：

| 層 | 做了什麼 |
|---|---|
| 軟陰影 | `VSMShadowMap`、`radius 4`、`blurSamples 12`（`PCFSoftShadowMap` 在 three 0.186 已被移除） |
| 接觸陰影 AO | `GTAOPass`，`radius .85`／`scale 2.0`／`samples 16`；開著時牌底下那片畫好的假影子關掉 |
| 暗角＋顆粒 | 自寫 `ShaderPass`，`vig .22`、`amount .034`，暗部多顆粒亮部少；放在 `OutputPass` 之後 |
| 靜止時精算 | 抖動取樣累積 24 格；壁爐的火只要求重畫、不重置累積 |
| 材質微結構 | 牌＝亞麻壓紋（`clearcoat` ＋ `clearcoatNormalMap`）＋層疊的側邊；桌布＝絨毛法線＋方向性高光（`anisotropy`）；木沿＝導管孔＋一圈銅鑲線；骰子＝法線凹點 |
| 幾何細節 | 椅子＝滾邊／釘扣凹陷／收分的腳＋銅腳套／木扶手蓋／冠條／各歪一點；牌庫＝每張錯開；手牌＝微微拱起；書＝往層板前緣靠、少數推回去 |

**沒做的三層**（原型裡留著，程式結構讓它們日後開得起來）：燈罩＝面光源、光暈、景深。

## 畫質三檔

設定頁多一列「畫質」（預設「自動」），`?fx=high|mid|low` 也可以直接指定，
console 用 `UD.fx()` 看現在幾檔、`UD.fx("high")` 現場換。

| 檔 | 誰 | 開哪幾層 |
|---|---|---|
| 高 | 有精確指標裝置且畫布 > 1100 | 六層全開 |
| 中 | 畫布 > 820 | 軟陰影＋材質＋幾何＋暗角顆粒；不做 AO（退回假的接觸陰影）、不做精算 |
| 低 | 手機，或 `prefers-reduced-motion` | 只留材質與幾何；整條後處理不建 |

自動檔會照 `fxRender()` 量到的每格毫秒數**自己往下降**（> 26 ms 就降一檔，只降不升，
前 30 格不算——那時候在上傳貼圖與編譯著色器）。使用者自己選了檔就鎖住不再自己動。

## 「改之前」那張是怎麼截的

`git worktree add /tmp/ud-before d842532`（這個 commit 的前一個）開一份獨立的檢出，
再用**跟新版完全一樣的流程**（`scripts/_browser.ts` ＋ 同一支截圖腳本 ＋ 同樣的
Emulation 1600×1000 DPR2）截一次。兩張的取景、人數、燈光條件都一樣，只有發到的牌不同。

**踩過一次的坑，記在這裡免得再犯**：第一版的「改之前」是用「複製一份 `docs/` 到暫存資料夾 ＋
自己開 `python3 -m http.server`」截的，那張圖**每張牌都只有角標、中間一片空白**。
牌面的邊框、點數、人像是由一張 SVG `<image>` 畫進貼圖的，角標的字是另外用 canvas 疊的
（`<image>` 載進來的 SVG 是密封的，讀不到頁面字型）——所以那張 SVG 沒載到的時候，
看起來就是「牌是空白的，但角標還在」。Francis 看到那張圖第一句就是「怎麼是空白的？」。
**要截舊版一律開 worktree 走原本的測試 harness，不要自己複製 docs/ 另開 server。**

## 還沒量到的

**真 GPU 上的每格毫秒數**。這台機器上的無頭 Chrome 走 swiftshader（純軟體算繪），
量到高 1725 ms／中 457 ms／低 125 ms——**那組數字只能看相對大小，不能當結論**
（真 GPU 大約是它的幾十分之一）。要在真機上看，開設定頁看「畫質」那一行的說明
（自動檔會寫現在實際在跑哪一檔），或 console 打 `UD.fx()` 看 `ms`。
自動降檔在那之前就已經在保護慢的機器了。

## 兩處刻意跟原型不一樣

- **桌布絨毛的回光顏色**：原型的 D 用 `fc × 1.35`，線上維持既有的 `fc × 1.6`
  （`sync()` 裡跟著王牌花色換的那條）。改它會動到王牌變色那條路，而且 1.6 是
  Francis 已經看了好幾天的值；差別只在 sheen 的染色深淺，這一版不動。
- **「畫質」與「立體鏡頭」兩列在平面模式也看得到**（跟既有的「立體鏡頭」一致）。
  要不要在平面模式收起來是另一件事，沒有一起改。
