給 Francis 看的頁：<https://claude.ai/code/artifact/a9b58c1d-52e3-4909-88ee-96bf57998557>

Francis 的原話：**「現在的畫面怎麼有顆粒在動的感覺？不是很喜歡。牌面也有點不清楚了。」**

## 一、顆粒在動 —— 是 bug，不是設計

顆粒著色器每一格都 `seed = Math.random()`，而壁爐的火每 90 ms 要求重畫一格
（`frame()` 裡的 `fireMoved`），所以**整張畫面的顆粒跟著火在爬**。
在中檔更明顯：中檔不疊精算，每次重畫都是直接畫到畫面上。

量到的（同一場、連拍兩格、間隔 300 ms，逐畫素平均差／255）：

| | 全幅 | 桌心 | 狀態列的字 | 書櫃 |
|---|---|---|---|---|
| 改之前 | 2.70 | 2.38 | 2.22 | 2.25 |
| 種子固定之後 | 0.92 | 0.18 | 0.14 | 0.76 |

改之後剩下的 0.9 是那張牌自己還在落定，不是顆粒——桌心與字已經完全不動。

還有第二個毛病：**靜止精算會把會動的顆粒平均掉**，所以停手幾秒顆粒會自己變淡，
濃度從頭到尾不一致。種子固定就沒這件事。

**但 Francis 最後的決定是「完全不要」**（2026-09-15）：顆粒整段從著色器拿掉，
那個 pass 只留暗角，改名 `FX_VIG`。要復活的話看 `FX_VIG` 上面那段註解。

## 二、牌面不清楚 —— 三件事，其中一件是真 bug

### (a) 圖集畫在牌面圖到齊之前，而且永遠不會補（真 bug）

牌面的邊框、點數、人像是一張 SVG 畫進貼圖的，角標的字是另外用 canvas 疊的
（載進來的 SVG 是密封的，讀不到頁面字型）。所以圖沒到的時候，症狀是
**「角標還在、中間一片空白」**——整副牌都這樣，而且一整局都不會好。

根因（用 CDP 在頁面裡記 `buildAtlas` 的呼叫點問出來的）：

```
buildAtlas  ← rebuildAtlas ← sync()      t=9363ms   ART 裡的牌面圖：0 張
boot() 等圖等到                            t=10026ms
boot() 的 rebuildAtlas                     t=10027ms  → 早退，因為牌組設定沒變
```

`sync()`（進牌桌、有人開局都會觸發）有機會在 `boot()` 還在 `await` 牌面圖的時候
就先畫一次圖集；那次畫出來整張是空的。而 `rebuildAtlas()` 只比「牌組設定變了沒」，
所以 `boot()` 後面那次就早退了——空白圖集從此定住。

修法：圖集多記一個**牌面圖的版號**（`ART.rev` / `S.artRev`）。圖到齊之後版號 +1，
`rebuildAtlas()` 就知道自己該重畫。另外牌面圖的載入也補了三件事：
等 `decode()` 完成才算載好（SVG 是畫到 canvas 那一刻才光柵化的）、
`onerror` 重試三次、一次最多載八張（一次丟 53 張進去，瀏覽器會有幾張直接失敗）。

驗到的：改之前三次無頭測試有兩次整副空白；改之後連跑六次都正常。
`agent/reports/0001-3d-fidelity/` 裡「改之前那張是怎麼截的」把這個症狀記成
「截圖流程的坑」——**那個結論不完整，它同時也是產品的 bug**，現在修掉了。

### (b) 暗角壓到自己的手牌

暗角原本 `vig .22`、`smoothstep(.28, .82, r)`——從畫面半徑 28% 就開始壓，
而手牌正好落在那條斜坡上，等於自己的牌被壓暗一成多。
現在 `.14` ＋ `smoothstep(.45, .96, r)`：四角照樣沉，桌心與手牌不再吃到。

### (c) 亞麻壓紋給太重

牌面的織理靠 clearcoat 的掠射反光。`clearcoatNormalScale .95` 的時候，
正面看牌會浮一層霧、點數邊緣被咬掉一點。收到 `.60`（`normalScale` 從 .55 收到 .40）：
斜著看織理還在，正面看乾淨。

## 三、順手改掉的一處浪費

高檔的靜止精算疊完（24 格）之後，火還是每 90 ms 要求重畫一格，
但那時候每格的權重已經不到 1/25——火在不在燒都看不出來，只是白花 GPU。
現在 `frame()` 的條件改成 `fxPending() || (fireMoved && !fxRefine())`：
高檔疊完就停手，中低檔的火照跳。

## 真 GPU 上的每格毫秒（補上 report 0001 欠的那一項）

`scripts/_browser.ts` 的 `Browser.start()` **不帶 `gl:true`** 就不會塞 swiftshader，
走這台機器的 ANGLE/Metal。M1 Ultra、1600×1000、DPR 2、單人四人局：

| 檔 | 在動：中位 | 在動：最差 | 靜下來 |
|---|---|---|---|
| 高（AO＋軟陰影＋精算） | 7.7 ms | 150.8 ms | 3.7 ms |
| 中（不做 AO 與精算） | 5.3 ms | 104.4 ms | 3.1 ms |
| 低（整條後處理不建） | 3.9 ms | 68.7 ms | 3.1 ms |

結論：**後處理不是瓶頸**——高檔在動的時候 7.7 ms，離 60 fps 的 16.7 ms 還很寬，
自動降檔的門檻（26 ms）只會在真的慢的機器上起作用。最差那一格是啟動成本
（上傳貼圖、編譯著色器），所以 `fxRender()` 的降檔判斷前 30 格不算。

## 踩到的坑

- **`pace=1` 截圖會讓手牌停在背面**。發牌是兩段補間（滑到桌上→拿起來翻正），
  節奏壓到 1 ms 的時候第二段會來不及接上，截出來手牌是背面朝上的。
  要截手牌正面，截圖腳本**不要帶 `pace`／`hold`**，用正常節奏等它自己落定。
- **`Math.random` 可以在頁面裡換掉**，換成固定種子的 LCG，三個變體就會拿到同一手牌；
  但如果那個變體的程式本身也在用 `Math.random`（例如會動的顆粒種子），
  隨機序列會被它吃掉而對不上——變體那邊要改用 `performance.now()` 之類的東西。
