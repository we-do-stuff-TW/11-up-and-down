# 0001. 立體牌桌加一層後處理，並用「不動就不畫」換品質

- 狀態:Accepted(2026-09-15 修正一處:顆粒那一層拿掉)
- 日期:2026-09-14

## Context(當時的情況)

立體牌桌的零件其實已經做得很細(仿真牌面、暖木書房、真骰子),但看起來還是像
乾淨的 CG 而不是照片。診斷之後問題不在零件,在光:整間房均勻亮、沒有接觸陰影,
所以牌看起來浮在桌面上、書櫃像一張貼圖、椅子沒有落地影子。

補這件事需要**後處理**(把整張算好的畫面再過幾道 pass),而後處理一向被當成
「網頁上玩不起」的東西:three 的 `GTAOPass` 要多一次深度法線 pass ＋ 16 次取樣 ＋
一道去雜訊,行動裝置上每格的預算根本不夠。

但這一層有一個別人沒有的條件:**它是 dirty flag 算繪——畫面不動就不畫**
(`frame()` 只在有補間、有火在跳、或有人滑過牌的時候才算繪)。牌局的絕大多數時間
畫面是靜止的。

限制:
- 沒有建置流程,`docs/index.html` 是單檔,three 用 CDN 動態 `import()`。
- three 的 addons 內部寫 `import ... from "three"`,裸名要有人解。
- 平面牌桌那一路不能受影響;2–10 人、手機到桌機都要能玩。

## 考慮過的選項

- **A 什麼都不做,只繼續加零件細節。** 最安全,但已經證明碰到天花板——
  再細的椅子腳,在沒有落地影子的地板上還是像貼上去的。
- **B 只改材質與幾何,不碰算繪管線。** 便宜(幾乎免費),也真的有效,
  但「牌浮在桌上」這件事解不掉——那要的是接觸陰影,不是更好的貼圖。
- **C 加後處理,全機型一律開。** 畫質最好,但手機會卡。
- **D 加後處理,分三檔,並利用「靜止」多花時間。** 選這個。
- **E 把 three 換成別的算繪器(或自己寫 shader 做 AO)。** 成本與風險都遠高於
  收益,而且會把「單檔、無建置」這個省事的前提丟掉。

## Decision(決定)

我們決定在立體牌桌上加一層 `EffectComposer`,並讓它的成本由「畫質三檔」與
「靜止時累積」兩件事吸收。

1. **三檔(`fxTier()`)**:高＝接觸陰影 AO ＋ 軟陰影 ＋ 暗角 ＋ 靜止精算;
   中＝去掉 AO 與精算;低＝整條後處理不建,只留材質與幾何那兩層(它們幾乎免費)。
   分檔不靠 UA 猜,看「有沒有精確的指標裝置」與畫布寬度,並且照量到的每格毫秒數
   **自己往下降**(只降不升)。使用者在設定裡選了檔就鎖住。
2. **靜止時累積**:停手之後把鏡頭抖半個畫素、把結果平均進累積圖,最多疊 24 格。
   鋸齒、陰影與 AO 的雜訊會自己收斂。壁爐的火只要求重畫一格、不重置累積——
   不然火每 90 ms 跳一次,累積永遠疊不完。
3. **後處理載不到就安靜地退回原本那條路**(`S.r.render`)。addons 靠 `<head>` 一張
   import map 解裸名;那張表的網址與 3D 那層 `import()` 的那一支刻意寫成同一個,
   模組才不會變成兩份。
4. 同一輪把材質微結構(亞麻壓紋、絨毛、導管孔、銅鑲線、法線凹點)與幾何細節
   (椅子滾邊釘扣、牌庫錯開、手牌拱起、書往前緣靠)一起做進去——這兩層在三檔裡都開,
   因為它們幾乎不花錢。

哪幾層要做是先在 `design/fidelity/` 做成「九層各自可開關」的原型、由 Francis
逐項切過之後定案的(面光源、光暈、景深三層不做)。

## Consequences(後果)

**正面**
- 牌真的落在桌面上了,書櫃有深度,椅子有落地影子。
- 靜止時的品質接近離線算繪——這是 60 fps 遊戲做不到、我們剛好能做的事。
- 慢的機器不需要人介入:量到慢就自己降檔。
- 後處理是可拆的一層:三層不做的效果(面光源、光暈、景深)日後要開,加一個 pass 就好。

**負面 / 代價**
- 算繪管線多了一條路。`frame()` 現在有三種出口(有東西在動／靜止時繼續疊／
  火要求重畫),比原本一行 `render()` 難讀。
- 多了一張 import map。**一份文件只吃得下一張**,以後誰要再加就得跟這張合併;
  這件事寫在 `<head>` 那張表旁邊的註解裡。
- 依賴 three addons 的 CDN。載不到會退回基本算繪(不會壞),但高檔就沒了。
- GTAO 的參數是這個場景量出來的(`radius .85`／`scale 2.0`)。動到桌子尺度或
  牌的厚度,這兩個值要重新量——預設值在這個場景等於沒開。
- 每格毫秒數在無頭 Chrome(swiftshader)上量不出有意義的絕對值,只能看相對大小;
  真 GPU 的數字要在真機上看。

## 2026-09-15 的修正:顆粒那一層拿掉

上線之後 Francis 的反應是「怎麼有顆粒在動的感覺?不是很喜歡」。
顆粒每一格換一次隨機種子,而壁爐的火每 90 ms 要求重畫一格——顆粒就跟著火在爬;
而且靜止精算會把會動的顆粒平均掉,濃度還會自己變淡。種子固定就兩個問題都沒了,
但 Francis 選「完全不要」,所以**顆粒整段從著色器移除**,那個 pass 只留暗角
(`FX_GRAIN` → `FX_VIG`)。暗角本身留著、收到 `.14` 並把起點往外推——
它跟顆粒是兩件事:暗角是把視線收回桌子中央的那一層。
細節與量到的數字見 [report 0002](../reports/0002-3d-grain-and-faces/README.md)。

**中性**
- 設定頁多一列「畫質」(預設自動)。
- 牌底下那片畫好的接觸陰影(`aoTex`)沒有拿掉——中低檔還在用它,
  高檔開著真 AO 的時候把它隱藏起來,不然同一道影子疊兩次。
