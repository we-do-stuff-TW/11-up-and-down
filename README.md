# 11 Up & Down

叫墩撲克。局數從每人 1 張爬到 11 張再降回 1 張，共 21 局；每局翻一張王牌，
用骰子宣告自己會贏幾墩，叫中才有分。

- **玩**：https://we-do-stuff-tw.github.io/11-up-and-down/
- **計分**：預設叫 0 中得 5 分，叫 n 中得 10+n；沒叫中扣 |實際 − 叫的| 分。三段都可以在房間裡改。
- **人數**：2～10 人。**不必先選**——幾個人進來就幾個人玩，人不夠房主可以加 AI 湊。
  牌不夠時階梯頂點自動下修：預設 64 張的話，6 人到 10 張、8 人到 7 張、10 人到 6 張。
- **牌組**：預設兩副 7–A 共 64 張。4 人要走完 1→11→1 至少需要 45 張。
- **規則**：叫墩方式、末位限制、鬼牌、牌組、三段計分都在等待房間裡調，只有房主按得動、全桌都看得到，
  開打就鎖住。見下面「房間規則」。
- **登入**：用 Google 帳號。名字與頭像自動帶入座位牌，換裝置還是同一個人，每場的戰績留著。
- **牌桌**：右上角可切「平面／立體」，選擇記在 localStorage。
- **音效**：右上角「音效」可關；關掉的狀態（和音量）也記在 localStorage。
- **分數的圖示**：座位牌下方一排「叫中的軌跡」，每局一格——綠＝叫中、紅＝沒中、框起來的是這一局。
  計分表格子裡的小點、表頭的局數階梯用同一套記號；不看數字也讀得出誰今晚穩。

## 房間規則

規則不是寫死的，是一桌一組。房主在等待房間裡調，改完存進 `cfg` 跟著這一桌走，
中途進來的人看到的跟桌上一致；按下開始就鎖住，整場不變。單人局在頂列「新局」裡調同一組旋鈕
（`RULE_UI` 那份描述兩邊共用，所以不會有一邊漏改）。

| 旋鈕 | 預設 | 其他選項 |
|---|---|---|
| 叫墩 | 依序公開叫 | **同時叫墩**：全桌同時選，選好先蓋著，全部放完才一起翻開 |
| 末位限制 | **the hook** | 不限制。hook＝最後一位不得讓總叫墩數等於總墩數，每局一定有人叫不中 |
| 鬼牌 | 不放 | **放兩張**（整桌固定兩張，不隨副數加倍） |
| 牌組 | 雙副 | 單副 |
| 最小點數 | 7 | 9／6／5／4／3／2（2 就是整副牌） |
| 叫中得分 | 10＋叫 | 10×叫／10＋叫² |
| 叫 0 中了 | 5 分 | 5＋該局張數 |
| 沒叫中 | 扣 \|差\| | 扣 10×差／扣差² |

**鬼牌**：不屬於任何花色（引擎裡是 `s = JS = 4`、`r = 15`）。比王牌還大，手上有跟牌花色也可以改出鬼牌；
鬼牌領出時桌上沒有花色要跟，大家自由出。兩張鬼牌撞在同一墩時先出的贏——跟雙副牌同點同花同一條規則。
翻開的王牌是鬼牌時該局無王，但鬼牌照樣最大。牌面五套共用一份（`jokerMid()`），
顏色取那副牌的裝飾色而不是花色色；3D 的圖集多一格 `15:4`，`jokers` 也進了 `rebuildAtlas()` 的快取鍵。

**同時叫墩的數字藏在哪**：`rooms` 是公開狀態，客端直接訂它的 realtime——放在那裡等於全桌都看得到。
所以還沒翻開的數字寫進 `hands.bid`（那張表 RLS 開著、一條 policy 都沒有），`rooms.bids` 上只留 `-1`，
意思是「這位放好了」：看得到誰決定了，看不到幾墩。全桌放完伺服器一次讀回來翻開。
需要 `supabase/migrations/0005_rules.sql`。

**引擎的入口**在 `window.UD.engine`（`newGame`／`startRound`／`applyBid`／`applyPlay`／`roundPoints`／`hookBlocked`…）。
3D 那層用不到，它存在是為了讓無頭瀏覽器把各種規則組合各打完一整場——頁面裡其他東西全包在 IIFE 裡，
CDP 的 `Runtime.evaluate` 只碰得到 `window.UD`。

## 測試

```
deno run --allow-read scripts/engine_test.ts     # 牌局引擎：各種規則組合各打完一整場
deno run --allow-read scripts/rules_test.ts      # 兩份規則對照：畫面 vs 伺服器
deno run -A          scripts/ui_test.ts         # 出牌的入口：無頭 Chrome 開真的牌桌
deno run -A          scripts/net_test.ts        # 連線那一段：假伺服器重演各種時序
deno run --allow-net supabase/functions/game/auth_test.ts   # 登入的簽章驗證
```

前兩支**不改也不需要任何產品程式配合**：它們照區段標記把「純計算」那一段從
`docs/index.html` 與 `supabase/functions/game/index.ts` 切出來，在沙箱裡求值
（`scripts/_engines.ts`）。切不到標記就直接報錯，不會安靜地少測一塊。

- **`engine_test.ts`** 打 321 場完整牌局（288 種規則組合各一場、2–10 人各一場、牌組邊角 24 種），
  一路檢查發牌、跟牌、the hook、贏墩、計分、收局。檢查用的「誰贏這一墩」「能出哪些牌」「這局幾分」
  是測試自己算的一份，刻意不呼叫引擎那份——兩邊算出來不一樣就是有一邊錯了。
  亂數是有種子的：失敗訊息帶著種子，`--seed=N` 照著跑一次就是同一場牌。
- **`rules_test.ts`** 把同樣的輸入餵給兩份規則引擎比對輸出（約五萬七千組）。
  不在比對範圍裡的是伺服器刻意獨有的三件事：斷線 30 秒 AI 接手、把房主送上來的規則夾回合理範圍、
  用真亂數洗牌。
- **`ui_test.ts`** 開無頭 Chrome 打真的牌桌，測「點下去會怎樣」：暗的牌點不動、按太久不算、
  手指滑開不算、按下與放開之間手牌被重畫還是要出得掉、平面與立體走同一個判斷、鍵盤那條路還在、
  點一下只出一張。立體那段用軟體 WebGL 開真的場景驗射線；three.js 從 CDN 載不到就跳過，
  不讓測試綁在別人的網路上。頁面只插兩個接縫（`<head>` 的門禁、`gotoLogin` 不跳走），
  接縫找不到就直接報錯（`scripts/_browser.ts`）。
- **`net_test.ts`** 重演那些真的網路重現不了的時序：樂觀先走、遲到的同一格（realtime 慢一秒的那條）、
  伺服器蓋章不重演動畫、過期的那一列、六秒保險絲、送不出去要退回、對手廣播、有人亂喊。
  伺服器換成假的（接縫 `window.__call`），每一列什麼時候到、內容是什麼都由測試決定。
- 入口是 `window.UD.engine`（`docs/index.html`）。**在那份名單上加東西，`engine_test.ts` 會要求它也被測到。**
- **測試自己也要驗**：故意把規則或判斷改壞，看它抓不抓得到（這四支都這樣驗過，每一條都當場被抓）。
  改壞之前先 commit——還原時 `git checkout` 會把還沒存的修改一起帶走。

## 頁面與牌桌是兩種東西

這個產品只有兩個視覺 register，分得很乾淨：

- **牌桌本體**是實體的——絨布、木頭、玻璃控制項、會隨王牌與局數變色的桌面。
  牌局中的對話框（新局、牌局結束）長在這一層，所以它們是浮起的玻璃卡片。
- **頁面**是印刷品——登入、大廳、開房頁、帳號／設定／規則。石板灰的地、用線分隔不用面、
  標題是 Bodoni、選中的東西底下一條銅線、整頁只有一處高對比。

頁面那一層的地吃 `--page` / `--page-deep` / `--page-glow`，**不吃 `--felt`**：
牌桌是酒紅的時候翻到設定，那一頁不該跟著變色。`--felt` 只由 `paintTable()` 依王牌與局數寫，
`:root` 給的初值刻意就是「空桌」的石板灰（`TABLE_NONE`，h250），跟 `login.html` 完全同一組值——
所以開機第一次上色就已經是對的顏色，不會先閃一下綠絨布。

帳號、設定、規則**是同一頁**（`#pg`）：上面那排章節名就是標題，切換只換底下那一疊，
從哪一顆按鈕進來都一樣，只是停在不同章。內容由 `paintMe()` / `paintPref()` / `paintRules()` 填，
規則與計分例子直接呼叫 `roundPoints()`，介面跟引擎不可能各說各話。
設定裡的「出牌速度」「音效」是轉接頂列那兩顆按鈕（`topTap()`），不另外記一份狀態——
大廳與開房頁沒有頂列，那兩項本來就沒地方調。

## 牌面

五套可切換的仿真牌，頂列「設定」裡選（有預覽，桌上立刻跟著換），記在 `localStorage` 的 `ud.deck`：

| 牌面 | 紙／墨 | 角標字型 | 特徵 |
|---|---|---|---|
| 愛德華金邊（預設） | 奶油紙、暗紅 | Libre Baskerville | 雙線金邊、稅章式黑桃 A、酒紅捲草牌背 |
| 賭場 | 亮白、正紅 | Barlow Semi Condensed | jumbo 角標、賭場藍菱格牌背 |
| 賭場四色 | 亮白，黑紅藍綠 | Archivo | 角標、點陣、人像衣袍都跟花色換色 |
| 鈔票雕刻 | 米紙，墨綠／胭脂單色 | Cormorant Garamond | 扭索紋邊框、人像名牌、玫瑰章 |
| 青花 | 冷白，鈷藍／釉裡紅 | Shippori Mincho B1 | 回紋邊、藍白人像、蓮紋牌背 |

版面五套共用：viewBox 0 0 100 140、實體牌的點陣排法、對稱角標、5.8% 圓角、四個自繪花色路徑（`SUIT_D`）。
每套牌面在 `DECKS` 裡只描述材質——紙色、墨色、字型、角標位置（依字型 Q 尾巴長度分別給）、人像配色、邊框與中央裝飾、牌背。
`faceSpec()` 把一張牌拆成 `art`（SVG 片段）與 `texts`（字），2D 的 `cardFace()` 直接組成 `<svg>`，
3D 把 `art` 包成獨立 SVG 載成圖畫進貼圖、字再用 canvas 依牌面字型疊上去——因為外部字型進不了當成圖片載入的 SVG。
J／Q／K 的人像是 `docs/cards/` 的英式雙頭人像，啟動時抓成文字、依牌面換色：2D 塞成頁面的 `<symbol>`，3D 包進每張牌的 SVG。
牌背同理：底圖是各牌面 `back.art()` 的 SVG，「11」與 UP & DOWN 由 `.back` 的偽元素（2D）與 canvas（3D）各疊一次，
垂直位置用 canvas 量過字型基線才設（`applyBackText()`）。

## 立體牌桌

立體版把牌桌換成一張 WebGL 畫布（three.js 由 CDN 載入），其餘一切不變——
規則引擎、連線層、計分表、規則說明都是同一份程式碼。3D 是加上去的一層呈現，不是另一套實作。

- **載不起來就沒事發生。** three.js 抓不到、或裝置沒有 WebGL，這一層就不啟動，平面牌桌照常運作。
  兩層之間只有一個接縫：`window.UD`。引擎那邊不知道有 3D 這回事。
- **文字仍然是 DOM。** 座位名、骰子、分數、狀態列疊在畫布上，位置由 3D 座標投影出來。
  向量字因此保持清晰，鍵盤與螢幕閱讀器也不會失去入口。
- **手牌有兩層。** 3D 負責畫，DOM 留下一層透明但可對焦的按鈕，貼在投影後的牌面上，
  所以 Tab 的焦點框會落在正確的那張牌上；滑鼠與觸控走畫布的射線命中。
  「這張能不能出」只判斷一次——就是那顆按鈕的 `disabled`，3D 的明暗與浮起跟著它，規則不會有第二份。
- **牌面是貼圖。** `drawFace()` 用 canvas 依平面版 `cardFace()` 同一套版面（viewBox 0 0 100 140）
  重畫成一張圖集，整副牌只上傳一次紋理。**改牌面時兩邊要一起改。**
- **同步是宣告式的。** `sync()` 只算「現在桌上應該有哪些牌、各自該在哪」，再讓場景收斂過去；
  誰要飛、飛多久是位置變了才產生的結果，不是一段段動畫腳本。所以狀態跳著來
  （連線延遲、對手秒出、重新整理）不會有牌卡在半路。
- **取景是算出來的。** 桌上真的有東西的地方各出一組點，用真正的透視反推鏡頭距離再重新對中——
  手牌離鏡頭比對面那半張桌子近了快一半，用平行投影估會低估它放大多少，下緣就會被切掉。
- **近端那塊扇形留給自己。** 座位不是把整圈平分的——鏡頭就架在我的位子上，平分的話靠我這半邊的兩位
  會被透視推到畫面最下緣，壓在我的手牌、墩堆與名牌上（7、8 人局時名牌直接疊在一起）。
  近端固定留 ±78°（`MY_ARC`）給自己，對手平分剩下的弧；人少時 2π/n 本來就更寬，4 人局還是正十字。
  每個座位再由左右兩邊的中線切出自己的扇形，手牌扇多寬、贏得的墩排幾疊、每疊多大都照它算，
  誰的東西都不會排到隔壁的位子上。
  檯面上出的牌不跟著座位的弧走，照人數平分成規規矩矩的一圈——哪張是誰出的由飛行交代。
- **牌庫放在自己左手邊。** 兩位之間的空檔看起來也放得下，其實是假的：那條空檔在墩堆那一圈以外
  會被兩邊的手牌各佔去半個扇形，8 人以上剩不到半張牌寬，牌庫一放上去就壓在人家手上。
  我這一側沒有任何人的手牌，半徑取在墩堆那一圈與桌沿之間，一張全尺寸的牌直放剛好進得去，
  翻開的王牌也離鏡頭最近、看得最清楚。自己的名牌因此改放右手邊（直式螢幕釘右下角）。
- **名牌會自己讓開。** 投影、夾回畫面內之後再跑一次分離：疊到的兩塊往重疊比較少的那一軸各退一半。
  遠端的座位投影後本來就靠得近，名字一長更會互相蓋住。
- **直式螢幕把桌子壓成橢圓。** 圓桌配上手機的畫面比例，怎麼取景都會有一邊留下大片空桌。
  壓扁的是位置，不是牌。
- **一間房，不是一塊布。** 桌子是整件東西：胡桃木圓沿、有厚度、立在深色地板上；背景與霧跟桌布同色相，
  換王牌時整個房間一起轉色（`roomColor()`）。光是一盞暖色頂燈加一間拼出來的房（PMREM 環境光），
  tone mapping 用 AgX，亮部慢慢收。
- **材質全是算出來的，不載圖。** 週期性值雜訊（`noiseField()`）疊幾個八度：桌布是燈罩下的光暈加絨面的斑駁與細纖維，
  再用 `sheen` 給布料在側光下那層帶染色的回光；桌沿是沿著圓周繞的年輪加細孔，上一層薄漆（clearcoat）；
  地板一點斑駁就好。每張牌底下貼一片接觸陰影（`aoTex()`），離桌面越高越淡——牌才是「放在」桌上，不是浮著。
  牌的厚度是牌寬的 0.7%（`THICK`），墩堆一疊的厚度就是那一墩的張數；贏得的墩不疊成塔，一墩一疊排成一列、每疊錯開約半張，一眼數得出來。
- **紙不反光。** 牌用 `MeshPhysicalMaterial` 把 `specularIntensity` 壓到 .26——一般材質的介電質反射固定 4%，
  頂燈一打牌面就泛白霧。牌的貼圖那道左上斜光在 3D 也只剩 .3。
- **手牌像真的握在手裡。** 所有的牌繞著牌中心下方 1.9 牌寬處的一個軸心轉（`HAND_R`）：下緣聚攏、上緣張開，
  左上角的點數排成一道弧；牌少時錯開寬一點，牌多時收到剩點數與一點花色露出來。右邊那張永遠壓在左邊那張上面
  （每張沿牌面法線多墊 .03），每張牌底下那片接觸陰影落在下面那張牌上，就是真牌扇開時牌與牌之間那道暗線。
  位移全在牌面自己的平面裡算，不沿世界的 y——沿 y 往下會同時往後退，退的量比墊高還大，順序就亂。
  只有「輪到你、但這張不能出」才壓暗到 .38；別人的回合與叫牌時整把牌保持乾淨，誰的回合由狀態列說。
  取景把最多張那一局的兩端與中間那張的四個角都算進去，含傾斜、扇形的轉角、能出的牌浮起的高度，下緣再多留一截；
  畫布的框因為任何原因變了（頂列換行、字型載好、開發者工具）都會重新取景（ResizeObserver）。
- **動作是幾條規則，不是腳本。** 發牌繞桌一張一張、我永遠拿每一輪的最後一張；王牌從牌庫頂端抬起、在半空翻正、
  整整齊齊放回牌庫頂端；出牌落地微微拍一下（`easeBack`）、對手的牌在半空翻正（`easeFlip`）；一墩打完不推牌，
  贏的那張上面亮起一盞小聚光燈（亮起／定格／收墩時暗掉，節奏跟 2D 同一份 `TUNE`）；收墩時贏的那張就地變成
  墩堆最上面那一疊、其餘幾張同路同速跟著飛，落定即消失；換局整桌翻背飛回牌庫頂端。
  補間支援個別屬性的曲線（`eases`）與沿途的弧線（`bump`）。

## 音效

沒有音檔。整套 Foley 是 Web Audio 即時合成出來的，所以不多一個 byte、不多一次 request，
而且每一下都不一樣——音高、時值、濾波都帶隨機扰動，連發二十張牌不會變成機關槍。

聲音照牌桌的世界觀做：深夜、暖、近。一間鋪了地毯的小房間（RT60 約 0.5 秒的合成脈衝響應），
近距離收音的紙與骰子，偶爾一顆電鋼琴式的琴音（FM，比例 1:1、調變指數快速衰減），
全部落在 F 大調九和弦裡。沒有遊戲機的「叮咚」。

- **每個 Foley 都是三層疊的。** 起音（接觸的那 1-3ms，寬頻）、本體（材質在響）、
  尾巴（桌面吸收掉的低頻加房間的殘響）。少了低頻那層，牌像掉在真空裡；少了殘響，像貼在耳朵上。
  紙牌認得出來全靠本體那段 1-2kHz 的「啪」——桌板的低頻只要大一點點就會把它整個蓋掉，
  正弦波的能量太集中了。
- **音高避開 300Hz 以下。** 手機和筆電的喇叭在那裡幾乎不出聲。「輪到你」原本寫在 A3／E4，
  在桌機上很好聽，在手機上等於沒有這顆；現在放在 A4／E5，要暗是用低通做的，不是用音高。
- **位置是算出來的。** 每個座位在耳朵裡有自己的方位：自己在正前方，對面在正中間但遠。
  遠的乾聲小、殘響多——距離感靠這個，不是只有音量。
- **接縫只有一個。** `render()` 最後一行 `SFX.frame(G, me, bi, …)` 把當下的牌局狀態遞過去，
  音效層自己跟上一次比對，差在哪就發什麼聲。所以平面、立體、單人、連線是同一份，
  引擎那邊不知道有聲音這回事；`window.SFX` 不在，那一行就什麼都不做。
- **狀態從載入就開始追，聲音等解鎖。** 瀏覽器規定沒有使用者動作之前不准出聲。
  如果等到解鎖才開始比對，第一次點擊會突然補放一整串早就過去的事。
  現在是一路跟著走、只把發聲擋在後面，接上的那一刻只會聽到「接下來」發生的事。
  第一局的發牌註定是安靜的，解鎖時補一聲很輕的洗牌當作房間醒過來。
- **洗牌在局與局之間。** 那 2.2 秒的空檔（`roundGap`）本來完全沒有聲音，
  而那正是荷官收牌、洗牌的時間。有人按「馬上開始」就把還沒放到的那一聲取消掉。
- **母線是一條混音鏈。** 乾聲與殘響匯進同一條匯流排，經 38Hz 高通、膠水壓縮、限幅、音量。
  十人局一輪發 110 張牌實測峰值 −19.7dB，沒有削波。

音效層那一段是 `docs/index.html` 裡的一塊（`/* 11 Up & Down — 音效層 */` 到那個 `<script>` 結束為止），
只有這一份。

要換成錄音（例如買了商用音效庫）不用重寫：
`SFX.load({ play:["sfx/card_a.wav","sfx/card_b.wav"] })`，
給幾個檔就輪流用，有錄音的那顆走錄音、其餘照舊合成，不用一次換完。
反過來要把合成的結果導出去，`SFX.bounce("play", {mine:true}, 1.2)` 會離線算成一段 AudioBuffer。

## 登入

身分是 Google 帳號（Supabase Auth）。`docs/login.html` 是唯一的入口，`docs/index.html`
在 `<head>` 就擋一次——**刻意不等 supabase-js 載完**，不然使用者會先看到一整張空牌桌閃一下。
那一關只同步讀 localStorage 裡的 session 鍵決定要不要轉走；真正的驗證在 `authBoot()`
與 edge function 那邊。從 Google 轉回來時網址上帶著 `?code=`，這種情況不能踢。
那段 `<script>` 排在字型那條 `<link>` **之前**：等待中的 stylesheet 會擋住後面每一支
inline script 執行，排在後面的話這一關要等 fonts.googleapis.com 回來才跑得到。

`authBoot()` 問完發現伺服器不認這張 session 時，走的是 `gotoLogin(true)`——**連 localStorage
那把鑰匙一起丟掉**（`forgetSession()`）。不丟的話 `<head>` 那一關會一直以為還登著，
每次開頁都先畫出一整張大廳、等問完才被踢回登入頁，而且會每次都閃。

呼叫 `functions/v1/game` 時 `Authorization` 帶的是**使用者自己的 access token**，不是 anon key——
anon key 誰都有，那不叫身分。伺服器用 `auth.getUser(jwt)` 換出 `auth.users.id`，
座位、房主、戰績全部認它。

舊的「localStorage 隨機 token」只剩一個用途：那台裝置以前匿名玩過的話，第一次登入時
把原本那一列 `players` 認領過去（`resolvePid`），桌上的座位與房主身分才不會斷。認領完
`token_hash` 就清空，同一個 token 不會被第二個帳號拿去。

**要開通得做三件事**（程式已經寫好，開了就會動）：

1. Google Cloud Console → 建一組 OAuth 2.0 用戶端 ID（網頁應用程式），
   已授權的重新導向 URI 填 `https://psuchtzacdppdpltpglg.supabase.co/auth/v1/callback`
2. Supabase → Authentication → Sign In / Providers → Google → 開啟，貼上 Client ID 與 Secret
3. Supabase → Authentication → URL Configuration →
   Site URL 填 `https://we-do-stuff-tw.github.io/11-up-and-down/`，
   Redirect URLs 加 `https://we-do-stuff-tw.github.io/11-up-and-down/**`（本機開發再加 `http://localhost:*/**`）

沒開通的話登入頁那顆按鈕會說「Google 登入還沒開通」，不會靜靜失敗。

## 手牌為什麼藏得住

發牌在 edge function 裡發生，手牌寫進 `hands` 表。那張表 RLS 開著、**一條 policy 都沒有**，
所以任何拿著 anon key 的瀏覽器都讀不到——包含房主的。每個人只會在自己的 API 回應裡
收到自己那份。`rooms` 表是公開狀態（檯面上的牌、叫墩、分數），本來就該所有人看得到，
但同樣沒有寫入 policy：牌局只能透過 edge function 推進。

`results`（戰績）是唯一有 select policy 的表，比對的是 `auth.uid()`——本人讀得到自己那份，
拿別人的 id 也查不到別人的。寫入一樣只有 edge function（service_role）做得到：
一場 21 局打完時寫，`(code, user_id)` 是唯一索引，重送不會變成兩筆。
