# 座位牌 · 三案

桌上浮在每個座位上方那一塊（`body.is3d .seat`，平面模式是 `.seats` 那一排）。
Francis 說「分數可以拿掉」「需要拿幾墩的設計再給我幾個」「整個狀態框有點小，看不是很清楚」，
所以三案的**共同前提**是同一件事：

- **分數拿掉**。總分在計分表裡有一欄，座位牌上那個 14px 的數字是重複的，
  而且它佔掉了第一行的整個右半邊。
- **整塊放大一級**：名字 13.5→15px、內距 8/12→11/15、骰子 31→34、圓角 12→14。
- 第二行的主角換人做：從「骰子＋小點＋11px 的還差 n」變成一件看得清楚的事。

差別在第二行怎麼講「還要拿幾墩」。

    python3 -m http.server 8771
    python3 shot.py "shots/all@1500x1180=index.html" "shots/table@1460x1060=table.html"

- `index.html` — 三案 ＋ 現況並排，每一欄由上往下是一個人打完一局會經過的六個狀態
  （還沒叫 → 叫 3 → 贏 1 → 剛好 → 超了 → 叫 0），最後一格是叫 8 墩的寬度壓力測試。
  **C 那一欄跟著 `docs/index.html` 的 `bidPips()` 同步**——原型比出貨的好看是會騙人的。
- `table.html` — 同樣三案 ＋ 現況，擺回桌上。牌與座位牌都是 1440 寬螢幕上的**真尺寸**，
  這一頁只回答一個問題：夠不夠看得清楚。
- `_seat.css` / `_seat.js` — 四頁共用的座位牌畫法。`C()` 與上線那一份一字不差。色票與骰子抄 `docs/index.html`
  （`--felt` 走 `paintTable()` 的 ♠ ＋深局版本，跟打到一半時的桌色一樣）。

## 三案

**A · 倒數**　第二行只講**你現在該做什麼**：「還要贏」11px 小、數字 30px 大（Bodoni，金）。
剛好了整句換成「別再贏了」轉綠，超了換成「多贏了 1」轉紅，叫 0 是「一墩都別要」。
已贏／叫的比例縮成卡片底緣一條 3px 的線。
*強*：一眼就是答案，不用數點也不用減。「剛好」那一格還多講了一句現在版本沒講的話——
手上還有牌、已經打平了，接下來要**閃**。
*弱*：看不到已經贏了幾墩（要從骰子減回去）。

**B · 拿／叫**　骰子退場——分母就是叫的墩數，不必再放一顆骰子講同一件事。
「1／3」大分數，左邊金色的數字每贏一墩跳一次；差幾用有底色的膠囊（金／綠／紅）講。
*強*：兩個數字都在，而且最省寬度——叫 11 墩跟叫 1 墩一樣寬，十個人的桌子也不會擠。
*弱*：要自己減一下才知道還差幾。骰子沒了，叫墩那一刻的儀式感也少一截
（叫墩動畫是丟骰子，見 `design/`／記憶裡的 updown-bid-animation）。

**C · 墩位**　完全不寫數字。叫幾墩就排幾格空墩位（15×20 的小牌格，中間那道是牌背的腰線），
贏一墩就填實一格。空的還剩幾格＝還差幾墩，數就好。剛好整排轉綠，超了後面長紅格。
五格一排會折行。
*強*：最像桌上真的東西，跟立體房間同一套語言；不必讀字，餘光掃過去就知道。
*弱*：叫 8 墩以上會折成兩排，整塊牌比另外兩案高一截。

## 量到的寬高

`measure.html` 把四版在最寬的狀態下實際量一次（px，`shots/measure.png`）：

| 叫 8 · 贏 5 | 桌機 1440 | 手機 390 |
|---|---|---|
| 現況 | 161 × 88 | 143 × 73 |
| A · 倒數 | 147 × 96 | 129 × 82 |
| B · 拿／叫 | 147 × 86 | 133 × 71 |
| C · 墩位 | 212 × 99 | 158 × 73（四格一排）|

兩件事值得記住：

1. **放大不等於變寬。** A 與 B 在最寬的狀態下都比現況**窄** 14px——第一行的分數拿掉、
   第二行的三段壓成兩段，省下來的比放大吃掉的多。長高的是 A（＋8px，那是大數字的代價）。
2. **會撞到東西的是窄螢幕，不是大螢幕。** 一支 390 寬的手機上，四塊牌繞著桌子擺，
   左右兩個人的牌超過 170 就會蓋到中間那一墩。C 五格一排時是 175，**已經蓋到**，
   所以窄螢幕改成四格一排（見 `table.html` 的 `@media (max-width:700px)`）。
   大螢幕反方向：2560 寬時牌桌那一欄還有 1915px，四塊 150px 的牌綽綽有餘。

## 定案：C

Francis 選 C，已經進 `docs/index.html`。實際接上去的跟這裡的原型差兩處小字：

- **「超 n」拿掉**、**叫 0 那格劃掉的墩位與「一墩都不要」也拿掉**。原型裡有，上線版沒有。
  因為挑案的同時 `17add5a`（畫面上那些小字解釋整批拿掉）立了一條規矩：灰色小字如果在解釋
  旁邊已經看得到的東西就刪。紅格本來就數得到、叫 0 骰子上那個 0 本來就是答案，
  留著就是同一件事講兩次。要加回來各是一行。
- **那句話搬進 `aria-label`**：格子只有眼睛數得到，讀螢幕的人數不到，
  所以整排的 aria-label 從「叫 3 墩，已贏 1 墩」補成「…，還差 2 墩／剛好／超了 1 墩」。

改到的地方：`.slots`（原 `.tally`）整段 CSS、`.seat-name` 15px、`.av` 21px、`.die` 34px、
`body.is3d .seat` 內距 11/15、`@media (max-width:700px)` 兩處；
`seatHTML()` 拿掉 `.seat-score`、`bidPips()` 換成墩位、`tallyScores()` 只剩計分表那一半、
`SEEN.scores` 整條清掉。

驗過：`engine_test` 321 場、`ui_test` 18 項全過；真的牌桌截了平面、立體、390 手機寬三張
（`scripts/_browser.ts` ＋ CDP `Page.captureScreenshot`，手機寬要用 `Emulation.setDeviceMetricsOverride`，
headless 的視窗夾在 500px 壓不下去）。

**還沒解的一條**：390 手機寬時，左右兩個人如果叫到 8 墩以上，那塊牌會蓋到中間那一墩。
現況也會（143px），C 是 158px，比原本多 15px。真正的解法是窄螢幕的座位牌擺位，不是再把牌縮小。

## 怎麼看

    cd design/seat && python3 -m http.server 8771
    open http://127.0.0.1:8771/index.html      # 四頁互相連得到

`file://` 直接點開會被同源政策擋住（css/js 是外部檔），所以另外有一份自帶一切的：

    python3 bundle.py     # → dist/index.html、dist/table.html、dist/phone.html，雙擊就開

`dist/` 是產生出來的，沒有進版本管理（`.gitignore`）。
