# 計分表 · 總分放不下（2026-09-22）

Francis 回報：6 人局的表頭大數字被切到。

    python3 -m http.server 8795     # 在這個資料夾
    open http://127.0.0.1:8795/     # index.html 是修改前／修改後的對照

`shots/` 是無頭 Chrome 跑真牌桌截的整張畫面（2 倍圖，不進版控）。

## 不是「被切到」，是互相疊上去

`table.score thead th .tot` 的字級寫死 `3.4em`，欄寬卻是 `(表寬 − 局數欄) ÷ 人數`。
1440 寬的螢幕上右欄 403px、表 378px、局數欄 66px，6 人時一欄 52px，扣掉 `th` 左右留白剩 **38px**。
34px 的 Bodoni（數字 advance .616em、負號 .467em）寫：

| 內容 | 要多寬 | 欄裡有 |
|---|---|---|
| `97` | 41px | 38px |
| `−12` | 53px | 38px |
| `125` | 61px | 38px |
| `−108` | 73px | 38px |

所以 **6 人局連兩位數總分都已經爆了**，跟分數大不大無關。
數字靠右對齊，溢出來的往左邊那一欄跑；`th` 是 `position:sticky;z-index:2`，
每一欄自己一個堆疊脈絡、照 DOM 順序疊，右邊那欄的底色壓掉左邊那欄的尾巴——
看起來就像被切掉。10 人局（`tighter`，總分 19px、欄內 26px）是 9 欄同時爆。

格子 `.p` 也在邊緣：1.9em × 等寬體，`+131`（「10＋叫²」那套規則一局的上限）要 46px，格子裡只有 36px。

第二輪的 README 寫過「第一輪 A 在 9–10 人時得把總分縮到 17px 的那個問題自己消失了」——
那句只對了一半：拿掉「拿／叫」解決的是**格子**，表頭那排大數字的寬度需求跟格子無關，沒跟著消失。
原型用的 `_data.js` 是一場兩位數分數的 4 人局，剛好照不到。

## 改法

字級不寫死，改成「這一欄有多寬，數字就多大」，再跟原本的上限取小的。
欄寬只有版面自己知道（表寬跟著視窗走、`.ledger` 的字級是 `vw`），所以用 container query：

- `th` 與 `td` 裡各包一層 `<span class="cq">`，`100cqw` 就是欄寬扣掉左右留白。
  **包一層是必要的**——containment 對 `table-cell` 無效，`container-type` 寫在 `th` 上不會生效。
- `renderLedger()` 多算兩個變數掛在 `#score` 上：`--totw` / `--cellw`
  ＝這張表最長的那個數字佔幾個 em（Bodoni 數字 .616em、負號 .467em；格子是等寬體，每個字 .6em，正負號一定有）。
  整張表共用同一個字級，欄跟欄才會齊。
- 格子多守一條：**不准追上總分**（`100cqw / var(--totw) / 1.25`）。
  總分被欄寬壓小時格子要跟著讓，不然會出現「表頭比內文還小」，
  「整張表只有這一排是亮的」就不成立了。原本的落差是 3.4 ÷ 1.9 ≒ 1.8，這裡守住 1.25。
- 每條都先寫一行舊的固定字級，再寫 `min(…)`：不認得 `cqw` 的瀏覽器落回原本的行為。

欄夠寬時 `min()` 取的還是原本那個值——**4 人以下完全沒動到**（總分 34px、格子 19px，對照圖切過去看不出差別）。

## 量到的結果（1440 × 900，三位數分數）

| 人數 | 欄內寬 | 修改前 | 修改後 |
|---|---|---|---|
| 4 | 64px | 34 / 19（沒溢出） | 34 / 19 |
| 6 | 38px | 34 / 19，**6 欄溢出** | 16.4 / 12.5 |
| 8 | 29px | 25 / 15.5，**8 欄溢出** | 12.5 / 10.0 |
| 10 | 26px | 19 / 13.5，**9 欄溢出** | 11.4 / 9.1 |

手機浮層（390 寬、6 人）15.6 / 11.7，立體牌桌與平面同一份 DOM、結果一致。
`ui_test` / `end_test` / `i18n_scan` 全過。

## 還沒決定的

十人局的總分只剩 11.4px。不是 bug，是右欄真的不夠寬：`.main` 的右欄 `clamp(330px,28vw,645px)`，
在 1440 上是 403px，扣掉局數欄之後十個人分 312px。要更大就得挪版面：

1. 就這樣（目前）
2. 人多時右欄加寬（7 人以上 28vw → 32–34vw），代價是牌桌那半邊變窄
3. 人多時改版面（總分兩行、或橫向可捲）

順手發現、這次沒動：表頭的「局」比底下的列號往左 3px（`th` 的 `padding-left` 是 .7em、`td` 是 1em）。
