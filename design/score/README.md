# 計分表 · 三案

牌桌右邊那一欄（窄螢幕是點開的整頁浮層）。現在線上那一版是 11px 的密表，
Francis 說「可以顯示大一些」，所以這三案的共同前提是**同一份資料，字大一級、列高一截**，
差別在於用什麼結構承載。

    python3 build.py            # 由 .def 組出 a/b/c.html
    python3 -m http.server 8771
    python3 shot.py "shots/a@1440x900=a.html" "shots/b10@1440x900=b.html?n=10"

- `_tokens.css` — 色票抄 `docs/index.html` 的 `:root`。`--felt` 是**牌局中**的桌色
  （`paintTable()` 的 ♠ ＋第 13 局深度 → `oklch(.229 .0513 168)`），不是大廳那張空桌的灰。
- `_data.js` — 假資料、真規則。計分公式抄 `roundPoints()`（叫中 10+叫、叫 0 得 5、沒中 −|差|），
  每一局所有人拿到的墩數加起來等於那一局的張數。種子固定，三案看到的是同一場牌。
- `a.def` / `b.def` / `c.def` — 各自的 CSS＋HTML＋畫法，共用上面兩份。
- `phone.html` — 三案並排的 390 寬 iframe。**headless 不能直接截 390 寬**：Chrome 會把視窗
  夾到最小 500px，媒體查詢不會觸發，只有 iframe 有自己的 viewport。

## 三案

**A · 記分簿**　局為列、人為欄，跟現在同一個結構，改的是尺寸與層級：總分是 Bodoni 31px
釘在頂上、列高 22→37px、格子裡的「拿／叫」升到 15px。局數那一欄底下多一條細線，長度＝那一局幾張，
整疊看下來就是 1→11→1 的階梯。
*強*：查得到任何一格，跟紙本記分簿同構，改動最小。
*弱*：欄寬被人數除。7 人以上要收掉「＋幾分」，9 人以上總分只剩 17px、名字放得下兩三個字（見 `shots/a10.png`）。

**B · 一人一列**　把表轉九十度。一列＝一個人：名次、名字、21 格軌跡（綠＝叫中往上、
紅＝沒中往下、高度＝分數）、總分 34px。列依名次排，誰在贏一眼看得到。點一個人展開他的逐局，
預設攤開「你」那一列。
*強*：人數不吃欄寬，十個人只是十列。「誰在贏」「我這場打得順不順」最快。
*弱*：要比「第 9 局大家各拿幾墩」得自己點開比對。四個人時直欄下半是空的。

**C · 一疊卡**　沒有橫表。頂上一條釘住的總分帶，底下一局一張卡，最新的在最上面，
卡裡每人一行「拿／叫 ＋分」，進行中那一局改顯示「還差幾墩」。
*強*：手機上不必左右看；一局的全貌最完整；十個人只是卡裡多幾行。
*弱*：要追一個人的整場得往下翻很多卡。總分帶在十人時要橫向捲。
