## 三案

**甲 · 帳本**　只有數字。格子 19px、總分 Bodoni 34px、列高 41px。
那一局賺最多的人只把數字提亮一階，不加底也不加框。最少的東西、最大的字。

**乙 · 刻度**　骨架同甲，數字**底下**多一條軌：中線是零，得分往右長、失分往左長，長度＝分數。
整片看下來多一層地形。條要放在數字底下不是背後——壓在字上兩邊都看不清（試過，很糟）。
弱點要說清楚：這套計分是「10＋叫」，叫中幾乎都落在 +11～+15，沒中大多是 −1，
所以條主要分得出的是「中／沒中」，那件事顏色跟正負號已經講完了。它多給的其實是 +5（叫 0 中了）跟大失分那幾格。

**丙 · 累計**　每格兩排：上排小字是那一局的增減，下排大字是打完那局的累計。
頂上就不放總分了——最後有數字的那一列（標「現在」、整張表唯一亮的一列）就是現在的比數，
而且往上看得到是哪一局被超車的。表會自動捲到「現在」，總分永遠在視線裡。
人一多收掉上排，只留累計。

## 踩過的兩個坑（都會靜靜地壞掉）

1. **`const top = …` 在全域會 SyntaxError**。`window.top` 是不可設定的全域屬性，
   同名的 `let`/`const` 直接讓整支 script 不執行，畫面一片空白、也不會有紅字提示。改叫 `hiScore`。
2. **class 名撞到共用樣式**。丙本來把累計那一排叫 `.r`，結果 `_tokens.css` 的紅花色 pip 是
   `class="tsuit r"`、表尾右側是 `.ft .r`，兩邊一起被 `display:block` 打到——
   紅心紅方的 pip 掉到下一行、表尾的頁碼變成 19px。改叫 `.run`。
3. 附帶一條：各案都寫 `table.sc td{text-align:right}`，特異性比 `_base.css` 的 `td.gut` 高，
   局數欄會被拉成靠右。`_base.css` 那條要寫成 `table.sc td.gut` 才壓得住。

## 第三輪：放大（2026-09-12）

Francis 在 2560 寬的螢幕上看到兩件事：計分表底下空掉一大片，以及「整體可以放大 150%」。

**空白那一片**是 `.ledger-scroll` 的 `max-height:min(66vh,640px)`。那條上限其實在做兩件事，
只有一件寫在紙上：一是不要太高，二是**擋住這一格的「天生高度」**。拿掉之後才發現第二件——
這一格的內在高度就是整張表（21 局將近 1400px），右欄會把 `.main` 那一列撐過一個畫面、
整頁長出垂直捲軸，連帶把手牌整排往下推（`ui_test` 的「按下與放開之間手牌被重畫」那條就是這樣掛的：
前面幾個互動共用同一組座標，位移之後點不到牌）。所以改成 `contain:size`：
版面貢獻是 0、由 `flex:1` 撐滿右欄，牌桌那邊完全不受影響。

**放大 150%** 不另外設一堆斷點：整張表的尺寸全部改寫成 `em`，尺度只綁在一處——
`.ledger{font-size:clamp(10px,.651vw,15px)}`，**1em = 10px 就是第二輪那一版**。
右欄是 `28vw`、一張表剛好要 `43em`，所以 `28vw ÷ 43 = .651vw`，字級跟欄寬永遠成比例，
不會出現「字大了但欄沒跟著寬」。右欄上限跟著從 `430px` 放到 `645px`（＝43em × 15px）。
於是：1536 以下跟第二輪一模一樣（只是底下不再空著），1536→2304 之間線性長大，2304 以上 1.5 倍到頂。
窄螢幕的浮層是整頁寬，尺度改看視窗：`clamp(10px,2.2vw,15px)`（43em 表 ＋ 左右 2.4em ⇒ 100vw ÷ 45.4）。

順手修掉一個靜靜壞著的東西：`@media (max-width:960px)` 那段浮層寫在通則**前面**，
媒體查詢不加特異性，所以 `.ledger-head` 與 `.ledger-scroll` 那兩條在手機上一直被後面的同名通則蓋掉
（手機的表頭留白其實是桌機那組）。現在那一段搬到這一節最後面，寫什麼就是什麼。
