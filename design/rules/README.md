# 房間的設定：三案（2026-09-13）

房間裡按「設定」之後那一面。**現在線上是整頁換掉**（`#rmBody` 收起來、`#rmEdit` 攤開）：
座位表消失，八個規則分兩欄攤在 1440px 上，中間一大片空白——選項不多，反而更難選。

**定案 B（2026-09-13），已經接進 `docs/index.html`**——底下「接進去之後」那一節記了實際踩到的差異。

這三案把它改成**一個展開來的視窗**。差別只有兩件事：**視窗停在哪裡**、**一次要你面對幾個決定**。
規則本身、選項文字、分數例子全部照 `docs/index.html` 的 `RULE_UI` 與 `roundPoints()`，沒有新發明。

## 跑起來

```sh
cd design/rules
python3 -m http.server 8778
open http://127.0.0.1:8778/          # 對照表（截圖 + 三案的取捨）
open http://127.0.0.1:8778/a.html    # 原型；底下那排切換器是原型才有的
```

參數：`?room` 從開房頁開始（自己按「設定」進去）、`?nodev` 藏掉切換器（`phone.html` 用這個）。
三案都吃 Esc 關閉、點視窗外面關閉。

## 改

改 `*.def`，`/*==HTML==*/` 之前是 CSS、之後是 HTML，然後 `python3 build.py a.def`（不給檔名就三案全 build）。
共用的底：色票與零件直接讀 `../room/` 那一份（`_tokens.css`、`_base.css`、`_head.html`…），
**不要在這裡複製第二份色票**；`_stage.css` / `_stage.html` 是背景那頁（定案的開房頁），
三案共用，它不是這一輪的題目。

截圖：`cd shots && python3 ../shot.py "a-set=http://127.0.0.1:8778/a.html?nodev"`。
手機寬不能直接截（Chrome headless 會把視窗夾到最小 500px），用 `phone.html`——一頁三個 390 的 iframe。

## 三案

| | 視窗在哪 | 桌子還看得到嗎 | 一次面對 | 代價 |
|---|---|---|---|---|
| **A 一張規則卡** | 畫面正中，560 寬 | 壓暗到剩輪廓 | 八排全部 | 桌子暫時不見了 |
| **B 側窗** | 右欄原位，往左長 60px | 全部看得到 | 八排全部 | 視窗窄，最小點數那七顆排得緊 |
| **C 拿近就地選** | 右欄那張紙自己浮起 | 全部看得到 | 一欄 | 想比較某一欄有哪些選項要先點開 |

**A**──八排收進一張紙。標籤靠右切齊，選項全部從同一條左界開始，由上往下一條直線掃完，
眼睛不必橫跨整個螢幕。最穩、最像一般對話框。手機上從底部貼上來。

**B**──位置就是答案：視窗從「設定」那兩個字底下長出來，貼在右欄原來的位置，
左邊座位表一格也沒被蓋到。牌數跟局數本來就是「幾個人」算出來的，改規則時看得到誰在座。
高度只取內容所需，不撐滿螢幕——撐滿就又變成一頁了。手機上從底部升起。

**C**──不另開一份：同一張規則單從邊上浮起變成視窗，同樣的順序、同樣的 leader dots，
只是每一行都按得下去；點一行，選項就在那一行旁邊跳出來。看的跟改的是同一張紙。
底下那顆銅色「開始」不必讓位，改完直接開局。手機上沒有左邊的空間，選單就地展開在那一行底下，
並自動捲到畫面中間。

## 三案都遵守的幾條

- **不加新的面**。視窗是這一頁唯一浮起來的東西：hairline 邊 + 投影 + 比地亮一階的漸層，
  裡面照舊「線分隔、選中的底下一條銅線」（`.ch`），沒有膠囊、沒有框、沒有第二顆銅色按鈕。
- **不加小字解釋**。`RULE_UI` 的 note 在 `17add5a` 整批拿掉了，這裡沒有把它們偷偷加回來；
  留下的只有讀數（牌數／最多每人／總局數、分數例子、房號人數）。
- **視窗不滿版**。滿版就是現在那個問題本身。

## 接進去之後（B，已上線）

動到的就是這幾塊：`.rm-edit` 系列 CSS 整段換掉、`paintRoomEdit()` 重排成頁首／一欄到底／頁尾讀數、
`paintRoom()` 裡那兩行 hidden 改成「座位表一直在、視窗浮上去」、`closeRoom()` 多清一個 class、
HTML 多一塊 `#rmScrim`。`onRulePick()`、`RULE_UI`、`roundPoints()` 一個字都沒改。

原型沒說、接進去才知道的四件事：

- **最小點數那一排在真資料下是兩行**。原型偷懶寫成「9／7／6…」，線上 `RULE_UI` 的文字是
  「9 以上／7 以上…」，七顆排不進 436 寬。兩行照樣對齊、照樣點得到，留著。
- **改規則沒送成的那句話要搬進視窗**。`roomErr` 本來印在右欄底下，而右欄整條被視窗頂掉了；
  現在 `paintRoomEdit()` 自己印一份在內容最上面。
- **`closeRoom()` 要清 `body.rm-set`**。視窗開著直接離開房間的話，桌子會留在壓暗的狀態。
- **小筆電寬（760–1000）視窗會吃到座位表右邊一點**。寬度加了 `min(436px, 100vw - 40px)` 保底，
  不讓它自己溢出畫面；被蓋到的那一小塊點外面就收掉。

改完的樣子：`shots/live-set.png`（桌面）、`shots/live-pick.png`（按下「單副」，
桌子中央的局數跟視窗底下的讀數同時從 21 變 13——這就是 B 案要的那件事）、
`shots/live-phone.png`（390，從底部升起）、`shots/live-close.png`（點外面收掉，右欄回來）。

## 接進 docs/index.html 要動的（當初的規劃，留著對照）

`paintRoomEdit()` 產生的那一塊（`#rmEdit`）與 `.rm-edit` 系列 CSS，加上 `paintRoom()` 裡
`$("rmBody").hidden = roomView === "rules"` 那兩行——改成兩者同時在，視窗疊上去。
選項還是 `data-rule` / `data-v`，`onRulePick()` 一個字都不用改。
C 案多一份「哪一行被點開」的狀態（原型放在 DOM 的 `.on` class 上）。

單人模式也走同一面（`MODE !== "net"` 那幾個分支），視窗裡的內容一樣，只是標題底下那行讀數
從「房號」換成「一個人打」。
