# 立體牌桌・仿真度比較原型（2026-09-14）

Francis 要「更細緻、仿真、最專業」的 3D。動手改 `docs/index.html` 之前，先在這裡把
**每一層效果拆開、可單獨開關**，用同一個場景比出「哪一層值得做」。

線上牌桌最不像真的地方不是零件細節，是**光**：整間房均勻亮、沒有接觸陰影、
書櫃像一張貼圖、椅子沒有落地影子。所以這裡的層次是照「投資報酬率」排的：
後處理光影 ＞ 材質微結構 ＞ 幾何細節。

## 跑起來

```sh
cd design/fidelity
python3 -m http.server 8791
open http://127.0.0.1:8791/index.html
```

拖曳轉鏡頭、滾輪推拉。右邊面板：**五個視角**（牌局／牌面／骰子／椅子／房間）、
**四個風格預設**、**九層各自的開關**、「拍前後對照」（拍 A 一張、拍目前這組一張，
疊起來用滑桿抹）。面板底下有 **每格毫秒數**，效能代價當場看得到。

## 這一頁為什麼可信

`pull.py` 把 `docs/index.html` 裡**已經在跑的**三段原封不動抄過來：

| 抄過來的 | 內容 |
|---|---|
| `_tex.js.part` | `mulberry32`／`noiseField`／`feltTex`／`woodTex`／`aoTex`／`makeEnv`／`ringTex`／`TABLE_H` |
| `_room.js.part` | `buildRoom()` 整段書房（地板、護牆板、書櫃＋書、壁爐、椅子、燈、地毯） |
| `_dice.js.part` | `diePaint`／`dieFaceMat`／`roundedBox`／`dieMesh` |

桌子的 Lathe 剖面、燈光參數、排位公式（`playSlot`／`fanSlot`／`handSlot`／`pileSlot`／
`deckSpot`）也照抄。所以「**A 現在**」是真的現在，不是重畫一份長得像的。

**兩處刻意不一樣**（比的時候要知道）：
- **牌面**是這一頁自己畫的簡化版（真的那份要人像 SVG 與整套字型）。比的是紙、光、邊。
- **桌布顏色**固定演「王牌方塊、第 6 局」那一桌（`oklch(.254 .0545 20)`）。
  線上是 `paintTable()` 依王牌花色與局數算出來的。

`docs/index.html` 改過之後重跑 `python3 pull.py && python3 build.py`；抄不到就直接報錯，
不會安靜地拿舊的比。`.part` 檔不要手改。

## 九層

| 層 | 做什麼 | 代價 |
|---|---|---|
| **軟陰影** | 換 VSM、半徑放大 | 每格多一次陰影圖模糊 |
| **燈罩＝面光源** | 頂燈從一個點換成 3.6×3.6 的發光面（RectAreaLight），聚光燈降到六成只留影子 | 幾乎免費（換一條 BRDF） |
| **接觸陰影 AO** | GTAO：所有「兩個面靠在一起」的地方自己變暗 | 多一次深度法線pass＋16 取樣＋去雜訊 |
| **光暈** | UnrealBloom，threshold 1.3（色調映射前的線性亮度） | 五層降採樣模糊 |
| **景深** | Bokeh，對焦在 `controls.target` | 一次全螢幕散景 |
| **暗角＋顆粒** | 自寫 ShaderPass，暗部多顆粒、亮部少 | 一次全螢幕、最便宜 |
| **靜止時精算** | 停手後抖動取樣疊 24 格 | 停手後才花，畫面不動時免費 |
| **材質微結構** | 牌＝亞麻壓紋（清漆層法線）＋層疊側邊；桌布＝絨毛法線＋方向性高光；木沿＝導管孔＋銅鑲線；骰子＝法線凹點 | 幾乎免費（清漆層會多一次採樣） |
| **幾何細節** | 椅子＝滾邊／釘扣凹陷／收分的腳／木扶手蓋／各歪一點；牌庫＝每張錯開；手牌＝微微拱起；書＝深淺前後不一 | 幾乎免費（多幾十個三角面） |

**代價要在真機上量**，面板底下的毫秒數就是那台機器的數字。`shots.ts` 跑的是
無頭 Chrome ＋ swiftshader（純軟體算繪），那裡的毫秒數只能看相對大小，不能當結論。

四個預設：**A 現在** ／ **B 光影修正**（soft＋area＋ao）／ **C 攝影感**（B＋bloom＋dof＋grain＋refine）／
**D 全套仿真**（C＋micro＋geo）。

## 量出來的幾個坑（改本體時會再踩一次）

- **`THREE.PCFSoftShadowMap` 在 three 0.186 已經被移除**（只會印一行 warning 然後退回
  `PCFShadowMap`）。真的還能「散開」的是 `VSMShadowMap`，`radius` 與 `blurSamples` 才有作用。
- **GTAO 的預設值等於沒開**。`radius .32／scale 1.1` 在這個場景下 AO 緩衝幾乎一片白
  （用 `__dbg.aoOutput('AO')` 看得到）。要 `radius .85／scale 2.0` 才真的把牌壓回桌面、
  把書櫃壓出深度。牌只有 .007 厚，半徑開太小什麼都遮不到。
- **Bloom 的 threshold 是色調映射「之前」的線性亮度**。`.82` 會把打亮的牌面整片吃進去，
  每張牌都在發光。要 1.3 以上，只讓火、燈罩、蠟燭過得去。
- **RectAreaLight 很會鋪光**：`intensity 16` 直接過曝（配合 bloom 就是一片白）。
  這裡用平均亮度量到 `area 2.6 ＋ 聚光燈 ×.60` 與 A 差不到 2%——比的是高光的形狀，不是亮度。
- **亞麻壓紋只給 `normalMap` 是看不見的**：紙很粗糙、鏡面反射又壓得很低，漫射光把起伏吃掉。
  要靠 `clearcoat` ＋ `clearcoatNormalMap`（掠射角的那層光澤），而且**鏡頭必須架在鏡射方向上**
  才看得到——這就是「牌面」那個視角的位置怎麼來的（牌的法線 `(0,.86,.51)`、頂燈在
  `(-.3,7.4,1.0)`，鏡射方向 ≈ `(.04,.22,.98)`）。
- **壓紋的節距要避開取樣極限**：一張牌寬 205 格時近拍剛好一格 2 個畫素，會冒出摩爾紋
  （看起來像數位髒污，不像布）。收到約 100 格就乾淨了。
- **壁爐的火不能重置「靜止精算」的累積**：火每 90 ms 跳一次，跟著重置的話永遠疊不完。
  火只要求重畫一格；平均起來就是「火在燒」，那正是要的。

## 為什麼這一層負擔得起後處理

3D 那層是 **dirty flag** 算繪——不動就不畫。所以昂貴的後處理只在「真的有東西在動」
的那幾格付錢，靜止時是零。而且靜止時還有大把時間可以燒：抖動取樣疊起來平均，
停手兩秒之後鋸齒、陰影雜訊、AO 雜訊全部收斂，接近離線算繪的乾淨度。
這是一般 60fps 遊戲做不到、我們剛好能做的事。

## 檔案

```
pull.py          從 docs/index.html 抄那三段（偶爾重跑）
_page.html       外殼：CSS ＋ 控制台 ＋ importmap
_scene.js        場景、九層效果、控制台接線（含 /*==TEX==*/ 等三個標記）
_tex.js.part     ↓ 抄過來的，不要手改
_room.js.part
_dice.js.part
build.py         拼成 index.html（可直接開）與 artifact.html（給 claude.ai 的版本）
shots.ts         無頭 Chrome 截圖：presets／views／layers 三種模式
shrink.py        截圖轉 1800 寬的 jpg ＋ 拼並排對照（原始 3200 寬整組 100 MB）
shots/           截圖（cmp-AD 是 A｜D 全幅並排，cmpV-* 是各視角的 A｜D）
```

除錯接縫在 `window.__dbg`：`aoOutput('AO')` 看 AO 緩衝、`gtaoSet({...})` 現場調 GTAO、
`setArea(i, k)` 現場調面光源與聚光燈。
